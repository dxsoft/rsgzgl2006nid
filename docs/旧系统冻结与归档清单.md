# 旧系统冻结与归档清单

Spring Boot + MySQL 主线已经承担工资业务迁移核心闭环。旧 Visual FoxPro 工程仍作为政策追溯、报表样式和历史逻辑参考，不再作为新功能开发主线。

## 1. 冻结原则

- 不在旧工程中继续实现新工资业务。
- 不把旧工程目录中的临时脏变更混入 Spring 迁移提交。
- 需要引用旧逻辑时，只做只读分析，并在新系统中实现。
- 旧系统变更如确需保留，必须单独提交并说明原因。

## 2. 当前需要关注的旧目录

- `FORMS/`
- `PROGS/`
- `REPORTS/`
- `LIBS/`
- `Menu/`
- `dxrsgzgl.*`
- `sys.ini`
- `temp/`

这些目录当前存在既有工作区变更，本轮迁移提交均未纳入。

## 3. 上线前建议

1. 对旧系统目录做只读归档。
2. 记录旧系统最后可运行版本的 commit。
3. 将旧工程目录从日常迁移提交范围中隔离。
4. 如果需要继续保留旧系统维护，单独开分支或独立仓库。

## 4. 迁移后使用方式

- 工资政策和历史逻辑：只读参考。
- 旧报表格式：作为新报表重建依据。
- 数据库表结构：继续作为新系统兼容层，直到现代 schema 明确。
- 退休工资：后续独立项目再评估旧逻辑。
