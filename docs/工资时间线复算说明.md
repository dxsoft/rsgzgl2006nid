# 工资时间线复算说明

## 目标

时间线复算用于按人员逐条重演历史工资变动，并把每条变动的规则试算结果与 `hisbase` 历史行金额进行对比。它适合排查“某个人从套改到当前工资是如何一步步变成现在这样”的问题。

## 当前实现

- 接口：`GET /api/salary/timeline/{personCode}`
- 可选参数：`limit`，限制返回的历史变动条数。
- 页面入口：人员详情区的“时间线”按钮。
- 返回汇总：检查条数、匹配条数、不一致条数、错误条数。
- 返回明细：历史行 ID、年月、变动类型、历史合计、基线历史行 ID、试算合计、差额、状态和工资项目变化。

## hisbase 链方向

`hisbase.sid` 指向的是下一条变动，不是上一条变动。

因此时间线排序按下面的链路处理：

```text
当前行 id -> 当前行 sid 对应的下一行 id -> 下一行 sid ...
```

服务会先找出未被其他行 `sid` 指向的起点行，再沿 `sid` 链向后遍历。若存在断链、孤立行或环，已访问行不会重复处理，剩余无法接入链路的行再按年月、金额、变动类型和 ID 做兜底排序。

## 试算基线

时间线逐条复算时，后一条变动使用前一条链路行的 `hisbase.id` 作为显式基线。这样同月多条变动不会因为按年月或金额排序而取错基线。

注意：`hisbase.id` 可能有前导空格，查询基线时必须保留原始 ID，不能 `trim`。

## 当前边界

当前版本是“基于历史变动事件的重演”：它读取既有 `hisbase` 变动行，按链路顺序逐条调用现有工资规则复算并对账。

它还不是完全脱离 `hisbase`、只根据基础信息自动生成所有应发生变动的独立状态机。下一步可以在这个能力之上继续做“基础信息驱动的应发生事件生成”，例如按任职、学历、考核、警衔、职级、法检等级等基础信息推导应发生的工资变动，再与历史链路做差异对照。

## 基础信息应发线

接口：`GET /api/salary/timeline-generated/{personCode}`

页面入口：人员详情区的“应发线”按钮。

当前第一版先做“事件生成独立、金额复算复用现有规则”的闭环：

- `dryjbxx`：参加工作时间不晚于 2006.07 的人员生成 `2006套改`。
- `dryzwbh`：任职信息 `srny` 不早于 2006.07 的记录，按次月生成 `职务变化`；首次转入 `21/22` 警员序列时生成 `警员套改`。
- `dxl`：学历取得时间 `bysj` 不早于 2006.07，且学历类别不是 `其他/其它` 的记录，生成 `学历变化`。
- `dndkh`：年度考核结果为 `优秀/称职/合格` 的记录，按人员序列生成次年 1 月正常档次/薪级事件。级别晋升需要准确重建 `xckhndjb` 起算状态，暂不在第一版生成，避免误报。

生成出的应发事件再与 `hisbase` 链按“年月 + 变动类型”匹配。匹配到历史行后，仍调用现有工资规则服务复算金额并比较差额；未匹配到历史行时标记为 `MISSING_HISTORY`。调标、津贴变化、手工特殊项等不是个人基础信息直接推导的历史行，暂计入“非生成历史”，不作为应发线错误。
