# 上线前历史写入操作与数据保护清单

本文用于工资业务迁移上线前的最后检查。范围只覆盖在职工资主线：待办生成、试算复核、历史写入、撤销写入、审计归档。退休工资和年终一次性奖金仍按独立后续项目处理。

## 1. 角色和权限

历史写入属于高风险操作，权限应与普通已办查看权限分开授予。

| 权限码 | 用途 | 建议授权对象 |
| --- | --- | --- |
| `SALARY_DONE` | 查看工资已办、写入计划、对照结果和流水 | 工资经办、复核、管理员 |
| `SALARY_HISTORY_WRITE` | 执行单条或批量写入 `hisbase` | 指定写入执行人员 |
| `SALARY_HISTORY_ROLLBACK` | 撤销已执行的历史写入 | 指定写入执行人员或管理员 |
| `SALARY_EXPORT` | 导出写入计划、流水、验收结果 | 需要归档或核查的人员 |

系统内置角色 `SALARY_WRITER` 已包含 `SALARY_HISTORY_WRITE` 和 `SALARY_HISTORY_ROLLBACK`。上线前应检查正式用户是否只给必要单位范围和必要菜单权限。

## 2. 写入前检查

执行历史写入前，应先完成以下检查：

1. 业务状态为已办，且已生成办理快照。
2. 写入计划预检状态为可写入，阻断项为 0。
3. 试算差异、字段差异、基础数据异常已复核或已登记为后期处理。
4. 单位数据权限已经限制到经办人员可管理单位。
5. 已完成数据库备份，并记录备份文件位置。
6. 写入人员确认本批次筛选条件、人数、变动类别和年月。

推荐先从少量单位或样本人员做正式写入演练，确认写入计划、`sid` 链恢复方案、写后对照和撤销流程均正常。

## 3. 单条写入流程

1. 在工作台打开工资已办业务。
2. 查看办理快照，确认本次试算结果和工资明细。
3. 打开写入预检，检查：
   - 待写入人员编码、单位编码、执行年月、变动类别；
   - 待承接的上一条历史行和下一条历史行；
   - `sid` 调整方案；
   - 字段映射和问题提示。
4. 点击确认写入历史。
5. 写入完成后查看写入计划和字段对照。
6. 导出写入流水归档。

写入成功后，系统会生成写入计划状态、写入历史行 ID、执行人、执行时间和审计流水。

## 4. 批量写入流程

1. 在历史写入计划中设置筛选条件。
2. 先执行批量预览，确认总数、可写入数、警告数、阻断数。
3. 对阻断或警告记录先处理基础数据或进行复核。
4. 确认可执行后再执行批量写入。
5. 记录本次返回的批次号，格式为：

```text
HWB-WRITE-yyyyMMddHHmmss-xxxxxxxx
```

6. 导出批量结果和流水，归档到上线批次资料中。

批量写入会跳过不可执行记录，不会因为单条阻断导致整个批次失败。批量结果中的 `success`、`failed`、`skipped` 必须和实际归档清单一致。

## 5. 撤销写入流程

撤销只用于上线演练、误写入、或明确需要回退的批次。撤销前必须确认已备份当前数据库。

单条撤销：

1. 打开写入计划。
2. 查看撤销预检。
3. 确认待删除历史行、上一条历史行、下一条历史行和 `sid` 恢复方案。
4. 点击确认撤销写入。
5. 查看撤销后的计划状态和流水。

批量撤销：

1. 在历史写入计划中筛选已执行且成功的记录。
2. 确认待撤销数量。
3. 执行批量撤销。
4. 记录批次号，格式为：

```text
HWB-ROLLBACK-yyyyMMddHHmmss-xxxxxxxx
```

撤销完成后，应抽查 `hisbase` 中被写入行是否删除，前后历史行 `sid` 是否恢复。

## 6. 批次号和审计归档

系统会为批量操作生成批次号：

| 批次前缀 | 含义 |
| --- | --- |
| `HWB-WRITE-...` | 批量写入历史 |
| `HWB-ROLLBACK-...` | 批量撤销写入 |
| `HWB-REVIEW-...` | 批量复测一致并标记通过 |

每个批次至少归档以下材料：

- 批量结果截图或导出文件；
- 写入计划 CSV；
- 写入流水 CSV；
- 写后字段对照结果；
- 本批次涉及单位、人员范围、变动类别、执行年月；
- 操作人、复核人、操作时间；
- 对应数据库备份文件名。

## 7. 数据备份和回滚

上线前建议使用 MySQL 逻辑备份，并保留文件校验值。

示例命令：

```powershell
$backupDir = "D:\rsgzgl2006nid\backup"
New-Item -ItemType Directory -Force -Path $backupDir
mysqldump -u root -p --default-character-set=utf8mb4 gzjsgl > "$backupDir\gzjsgl-before-history-write.sql"
Get-FileHash "$backupDir\gzjsgl-before-history-write.sql" -Algorithm SHA256
```

回滚策略分两层：

1. 优先使用系统撤销写入，按写入计划恢复 `hisbase` 链路。
2. 如果批量撤销不能覆盖异常场景，停止服务并从备份恢复数据库。

恢复数据库前必须确认：

- 当前服务已停止；
- 备份文件和目标库一致；
- 已保留当前异常库的临时备份；
- 恢复后重新运行验收脚本。

## 8. 上线前验证命令

优先运行上线前门禁脚本，脚本会检查服务、历史写入权限、系统权限回归、核心迁移样本门禁、打包，并生成归档报告：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\verify-launch-readiness.ps1
```

报告默认生成在：

```text
backend\target\launch-readiness-report.txt
```

如果服务正在运行且只想做快速检查，可以临时跳过会锁定 jar 的打包步骤：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\verify-launch-readiness.ps1 -SkipPackage
```

上线门禁通过后，可以执行受控历史写入演练。该演练使用 2099 年临时办理记录，完成写入后会撤销并校验链路恢复：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\verify-history-write-rehearsal.ps1
```

演练报告默认生成在：

```text
backend\target\history-write-rehearsal-report.txt
```

准备真实小批次前，先生成“只预览、不写入”的真实候选清单。该脚本只读取真实已办历史事件并调用试算预览接口，不创建已办 case、不生成历史写入计划、不写 `hisbase`：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\build-real-history-write-precheck.ps1 -ScanLimit 300 -Take 5
```

候选清单默认生成在：

```text
backend\target\real-history-write-precheck.tsv
backend\target\real-history-write-precheck.txt
```

如需从当前基础信息和工作台预览接口中寻找“尚未写入历史、可作为真实办理入口”的候选人员，可执行真实可写候选扫描。该脚本只读取预览接口，不生成待办、不完成 case、不生成写入计划、不写 `hisbase`：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\scan-real-writable-candidates.ps1 -Start 2025-01 -End 2026-06 -OrgLimit 80 -PerPreviewLimit 100 -Take 20
```

扫描结果默认生成在：

```text
backend\target\real-writable-candidates\real-writable-candidates.tsv
backend\target\real-writable-candidates\real-writable-candidates.txt
```

候选经业务确认后，可以先做“只完成办理和写入预检、不执行写入”的闭环验证。默认只确认预检，不自动复核试算风险：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\run-real-writable-candidate-precheck.ps1 -Take 3
```

如果候选属于目标月旧历史不存在导致的 `DIFFERENT`，需要先复核试算风险再确认写入预检，可显式加 `-ReviewBeforeConfirm`。该模式仍不调用写入执行接口，不写 `hisbase`：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\run-real-writable-candidate-precheck.ps1 -Take 3 -ReviewBeforeConfirm
```

候选预检报告默认生成在：

```text
backend\target\real-writable-candidate-precheck\candidate-precheck-report.txt
backend\target\real-writable-candidate-precheck\candidate-precheck-results.tsv
```

候选写入预检为 `READY` 后，可以做真实最小写入演练。默认只取 1 条，执行写入、导出字段对照和审计、随后立即撤销，并保存写入前、写入后、撤销后的历史快照：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\run-real-writable-candidate-pilot.ps1 -Take 1
```

真实候选写入演练报告默认生成在：

```text
backend\target\real-writable-candidate-pilot\candidate-pilot-report.txt
backend\target\real-writable-candidate-pilot\candidate-pilot-results.tsv
```

如果需要继续推进真实小批演练，可执行默认“写入后撤销”模式。脚本会先备份受影响人员的应用层历史快照，只有预检可执行时才写入；写入后立即导出对照和流水，并撤销恢复：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\run-real-history-write-pilot.ps1
```

真实小批演练报告默认生成在：

```text
backend\target\real-history-write-pilot\pilot-report.txt
backend\target\real-history-write-pilot\pilot-results.tsv
```

生产权限快照和数据治理台账：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\export-production-permission-snapshot.ps1
powershell -ExecutionPolicy Bypass -File scripts\build-production-data-governance-ledger.ps1
```

从仓库根目录运行核心迁移门禁：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\verify-core-migration.ps1 -FailOnUnexpected
```

只验证系统权限和工作台闭环：

```powershell
cd backend
$env:DB_PASSWORD='<your-local-password>'
mvn -Dtest=SystemPermissionRegressionTests test
```

打包并启动：

```powershell
cd backend
$env:DB_PASSWORD='<your-local-password>'
mvn -DskipTests package
Start-Process -FilePath "java" -ArgumentList @("-jar", "target\rsgzgl-backend-0.1.0-SNAPSHOT.jar") -WorkingDirectory "D:\rsgzgl2006nid\backend" -WindowStyle Hidden
```

启动后检查：

```powershell
Invoke-WebRequest -UseBasicParsing http://127.0.0.1:18080/
```

## 9. 暂缓项

以下内容不进入本轮上线主线：

- 退休工资独立项目；
- 年终一次性奖金；
- 差异原因自动归类；
- 历史特殊记录的全部自动化修复。

这些事项可以继续通过基础数据治理、验收问题台账和后续专项项目处理。
